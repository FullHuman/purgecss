---
"rollup-plugin-purgecss": minor
---

Make the plugin work with Rolldown and Vite. With Rolldown, the transformed CSS files are now marked as JS modules (`moduleType: "js"`), which Rolldown requires since it no longer bundles CSS; Rollup ignores it. With Vite, where every build failed, the plugin now detects Vite and hands the purged CSS back to Vite's CSS pipeline instead of a JS module, including for `?inline` imports; it must be in the `plugins` array, possibly through `perEnvironmentPlugin` (with Vite 7 and later, the build fails with an explanation when it is in `build.rolldownOptions.plugins` or `build.rollupOptions.plugins`, or has `enforce: "post"`, where it cannot see the CSS), resolves the relative `content`, `skippedContentGlobs` and `output` paths from Vite's `root`, only gives to `output` the CSS that Vite bundles in the CSS files of the client environments (not the CSS imported with `?inline` nor the CSS of the `<style>` elements and `style` attributes of the HTML), does nothing with `vite serve`, and leaves CSS modules (`*.module.css`) untouched with a warning, as Vite has already renamed their classes. `rollup` is now an optional peer dependency. The `output` path now has its directory created when it does not exist instead of failing with `ENOENT`. The `insert` option, which broke the build, now inserts the purged CSS in the `<head>` of the document, and the `contentFunction` option, which was ignored, now gives the content of each CSS file; when both are set, `contentFunction` is used instead of `content`. The CSS given to `output` is now in the order the files are imported instead of the order they finished purging, which changed between builds; it no longer misses the files restored from a Rollup `cache`, and in watch mode the CSS of a module transformed again is no longer added a second time, the modules no longer part of the build are left out, and `output` is emptied when the build no longer has CSS files. The content files are now watched, also after a build that failed because of one of them, and the CSS files are purged again when the build reuses a Rollup `cache`, so changing the content in watch mode purges the CSS again instead of keeping the old CSS; content files are only read and extracted again when they changed instead of once per CSS file. `content` is now optional (e.g. with `contentFunction`), with a warning when neither is set. With `sourceMap`, the map is inlined in the purged CSS exported by each file with Rollup and Rolldown (the CSS given to `output` has no map), and handed to Vite with Vite. The default `exclude` is now `"**/node_modules/**"` instead of `"node_modules/**"`, which only matched the `node_modules` directory of the current working directory: the CSS of the dependencies is no longer purged when they are in another `node_modules` directory, e.g. hoisted to the root of a workspace or in pnpm's store. The `dest` option, which had no effect, is deprecated. With Vite, the URLs of the assets in the CSS given to `output` (e.g. `url(./bg.png)`) are now the URLs of the emitted files instead of Vite's internal placeholders.
