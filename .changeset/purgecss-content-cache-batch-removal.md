---
"purgecss": minor
---

Add `ContentCache` and the `PurgeCSS.contentCache` property, so integrations that run PurgeCSS many times (a PostCSS plugin called once per CSS file, a bundler in watch mode) only read and extract a content file again when its modification time, change time, size, inode or extractor changed. Runs at the same time share the files being read and extracted, so each file is extracted once even when a bundler processes many CSS files concurrently; a file modified or changed (for example its modification time set back) less than 2 seconds before it was read is extracted again on the next run; `keys()` lists the cached files and `prune(paths)` and `delete(path)` remove the entries of files no longer used, and the paths given to `prune`, `delete` and `has` are resolved from the current working directory. Globs are still resolved on every run. Content files are now read and extracted in parallel, at most 32 at a time for all the runs of the process together, and the selectors of each file are merged as soon as it is extracted: extractors may be called concurrently and out of file order, so they must not keep state between files; when several files fail, `purge()` still rejects with the error of the first one in file order. The unused rules are removed in one pass once the stylesheet has been walked through instead of one by one, which gives the same output and makes the walk about a third faster on large stylesheets such as Tailwind CSS 2. Raw CSS given with a `name` now uses it as its path in source maps, resolved like the path of a CSS file: the map `sources` are relative to the directory of `sourceMap.to`, which defaults to the name. The selectors kept by a `ContentCache` share one string per distinct selector, so the cache holds about a third of the memory it would otherwise. `matchesPattern`, which tells if a value matches a pattern of the options (a regular expression, a string written between slashes or an exact string), is now exported.
