---
"purgecss-webpack-plugin": minor
---

Support Rspack and CSS modules, extract the content once per compilation and fix source maps. The plugin no longer imports `webpack` at runtime: it uses the classes of the compiler running it (`compiler.webpack`), so it works with Rspack 1 and 2 without webpack installed; `webpack` and `@rspack/core` (`^1.0.0 || ^2.0.0`) are optional peer dependencies, and the TypeScript declarations no longer import webpack (`apply` takes a `CompilerLike`). It purges the CSS assets in the `processAssets` hook at the `PROCESS_ASSETS_STAGE_ADDITIONAL` stage, the stage of the deprecated `additionalAssets` hook it used before. The used classes of CSS modules are kept: the plugin reads the export maps of the CSS modules (mini-css-extract-plugin, `CssExtractRspackPlugin` of Rspack 1.1 or later, the native CSS of Rspack 1.3 or later, and `experiments.css` of webpack 5.97 or later) and keeps the hashed class names whose export name is found in the content, or is a word of a selector found in the content, where it used to remove every hashed class. The content files are read and extracted once per compilation for all the CSS assets instead of once per asset. In watch mode, the content files are added to the file dependencies of the compilation, along with the target of a content file that is a symbolic link, so changing one purges the CSS again, and only the files that changed are read again. A content file that does not exist is now reported as an error of the compilation instead of an error thrown by the hook, and is watched: the compilation runs again once it is created. Source maps of the purged CSS now point to the original CSS files instead of `<input css ...>`, and the purged CSS no longer gets a second `sourceMappingURL` comment.
